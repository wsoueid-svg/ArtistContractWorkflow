# Contract Editor • Increment 1 staging handoff

App: 6ace931c17036220281d8839. Not published. No secrets, connectors, workflow activations, dispatch changes, or signature changes were added.

## Baseline
Before implementation, contract-lab was absent, generateSmartContract used shared/pdfshift.ts, and ContractFillForm had four existing steps. No existing idempotent template seeder was located; this deviation was reported before using staging-only upserts.

## Implementation
The four-step form opens a fifth same-dialog document view, with a full-screen mobile layout and Back to form. Canonical blocks are extracted from the existing template renderer using non-visible markers; legal prose comes from the existing clause packs/officialTerms, not a second legal-text copy. Payment context was extracted into shared/contractSchedule.ts without changing calcDeal or dealCardTerms.

Editable clauses and appendices support rich text, insertion, removal, movement within protected sections, restoring master wording, undo and redo. Representation, event source, signatures and economics are protected in the UI and validated again on the server. Draft writes only target ContractDraft. The server supplies the approval identity, time, revision and lock token.

Existing draft updates use database updateMany with an id + expected revision + lock-token predicate and $set. A competing save was exercised: the winner stayed at revision 3 and the stale browser save returned 409. This is a conditional update, not a read-then-write claim. Initial creates are separate draft records; no unique create-if-absent guarantee is claimed (the platform rejected unique schema keywords).

Recovery copies are browser-local and keyed by authenticated user, Show and draft identity. The UI distinguishes browser-only changes from approved server saves. Continue editing draft shows revision, save time and approver; its list refreshes on remount rather than inheriting the app's two-minute cache.

Edited documents never go to the existing PDF generator. The button is disabled with the required next-increment message, and saved edited drafts are also rejected by the generator. No Increment 2 edited-generation/revision workflow or Increment 3 dispatch/history feature was implemented.

## Manual handover
Open the fictional Show's Contract tab, choose Fill & Generate Contract, select Analog entertainment (EN), complete the form and Review document. Type in a clause; apply bold, italic, underline and both list types; restore wording; insert, move and remove clauses/appendices; exercise undo/redo. Try typing or pasting into the representation and economics blocks (they must remain read-only). Save, close and reopen. Open the same draft in two tabs, save in one, then attempt a save from the other and verify the conflict and retained browser copy. Finally test Recover, Compare and Discard on a fresh reopen. Do not dispatch, sign or publish this staging fixture.
